How requests reach Controls

  1. Operator’s browserOpens the Streamlit dashboard
  2. →↓
  3. Streamlit serverRuns the UI and sends authenticated HTTP requests
  4. →↓
  5. JAVES-AI Controls APIOwns accounts, cases, decisions, and access to results

Controls coordinates the backend services and workers. Routing produces the route SVG, while the dashboard displays the image fetched through Controls. The dashboard accesses case data and media through the API.

dashboard/app.py
Chooses connected mode when TRACE_CONTROLS_URL is set. Otherwise it starts the local simulator.
dashboard/search_dashboard/live.py
Implements connected sign-in, case screens, polling, review actions, and media display.
dashboard/search_dashboard/controls.py
Sends requests with bearer authentication and idempotency keys where required. Translates API and network failures into UI messages.
javes_main/api/
Hosts the existing Controls endpoints in the backend. The integration patch adds the dashboard and updates the root README.

What happens during a case

  1. Sign in. Streamlit posts to /v1/auth/login and keeps the returned bearer token in its server-side session.
  2. Find or create a case. GET /v1/cases lists existing cases. To create one, the dashboard posts the case details and staged reference-image key to /v1/cases.
  3. Open the case view. While the case screen is open, Streamlit requests /v1/cases/{case_id}/view every five seconds. The response includes status, candidates, progress, and any available media references. Streamlit requests route SVGs and live JPEGs from Controls using the session token.
  4. Review a candidate or close the search. The dashboard sends the action to Controls. Controls checks permissions and owns the resulting state. The case view refreshes to show that state.
What if creating a case times out?

Controls might already have accepted the request. If the operator resubmits the same form in the same session, Streamlit reuses the original payload and Idempotency-Key. Controls can return the existing case without creating a duplicate.

Run it locally

1. Apply the patch in a clean clone

Put the HTML guide and the patch in the same directory to keep the download link working. Run these commands from the directory containing the patch.

git clone https://github.com/arystan01/tracking_person_across_multiple_cameras.git trace-integrated
git -C trace-integrated switch -c feature/dashboard-controls-integration
git -C trace-integrated apply --check "$PWD/dashboard-controls-integration.patch"
git -C trace-integrated apply --index "$PWD/dashboard-controls-integration.patch"

Applying the patch stages the files locally. A teammate with write access can commit them, push the feature branch, and open a pull request.

2. Start the backend and Streamlit

Follow the backend README’s configuration and start order to run Main/Controls and its dependencies. In a second terminal, from the directory containing trace-integrated, run the dashboard commands below. Backend startup instructions

cd trace-integrated/dashboard
python -m pip install -r requirements.txt
TRACE_CONTROLS_URL=http://127.0.0.1:8080 python -m streamlit run app.py --server.address 127.0.0.1

Open the URL printed by Streamlit and sign in with a backend-issued account. New cases require a reference image that a backend operator has staged in the shared artifact store under cases/<case-id>/. Enter that key with the site version and last-known information.

For the standalone demo, run the Streamlit command with TRACE_CONTROLS_URL unset and use the demo credentials in dashboard/README.md.
