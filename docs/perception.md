# Perception: YOLO26 + ByteTrack + OSNet

Perception — «глаза» системы. Он получает пробу «проверь камеру B с 05:16 по
05:18», смотрит только этот кусок видео и отвечает: какие люди там были, когда,
где на кадре и насколько каждый похож на цель. Куда человек пошёл дальше, решает
Routing; Perception про граф здания ничего не знает.

Код: `javes_perception/`. Production worker забирает `GALLERY_BUILD`, `PROBE`
и `PERCEPTION_CANCEL` через Main HTTP pull/lease API. Локальный `PerceptionPort`
сохранён только для core/unit tests.

## Конвейер

```text
ProbeJob -> видео окна (5 кадров/с) -> YOLO26 (люди) -> ByteTrack (треки)
         -> фильтр качества кропов -> OSNet (вектор 512) -> вектор трека
         -> сравнение с галереей цели -> калибровка -> ProbeResult
```

| Шаг | Что делает | Файл |
|---|---|---|
| Видео | По `perception.yaml` находит файл камеры и время его первого кадра, вырезает окно пробы, берёт ~5 кадров в секунду. Время кадра = старт файла + номер кадра / fps. | `video.py` |
| Детекция | **YOLO26** (`yolo26n.pt`, Ultralytics) ищет только класс «person». | `models.py` |
| Трекинг | **ByteTrack** связывает рамки одного человека между кадрами. Трекер сбрасывается на каждой пробе, чтобы ID не путались между камерами. | `models.py` |
| Фильтр кропов | Кроп не идёт в Re-ID, если человек обрезан краем кадра, перекрыт другим человеком больше чем на 30 %, слишком мал (< 48 px), низкая уверенность детектора (< 0.4) или странные пропорции. | `worker.py` |
| Re-ID | **OSNet-AIN** (`osnet_ain_x1_0`, веса MSMT17) превращает кроп в вектор «внешности» из 512 чисел. Кроп прогоняется дважды, обычный и зеркальный, векторы складываются (flip TTA). | `models.py` |
| Вектор трека | Взвешенное среднее векторов трека (вес = уверенность × размер), затем 20 % самых непохожих на среднее кадров выкидываются и среднее считается заново. | `worker.py` |
| Сравнение | `cosine` = максимум косинусной похожести с векторами галереи цели (фото + подтверждённые оператором треки). | `worker.py` |
| Калибровка | `appearance_score = sigmoid(a·cosine + b)`; `a`, `b` подобраны на Market-1501 (см. ниже). | `worker.py` |

## Что отдаётся наружу

Строго по контрактам 3, 6, 7 (`docs/components.md`, раздел 1):

- `tracklets` и `candidates` — только люди со score выше `score_floor`;
  `n_tracklets_total` — все люди в окне до фильтра.
- `tracklet_id` и `candidate_id` вычисляются из содержимого (кейс, камера, время
  начала, первая рамка), поэтому повтор пробы даёт те же ID.
- `bbox_first` / `bbox_last` — `[x, y, w, h]` в пикселях кадра.
- `clipped_start` / `clipped_end` — человек уже был в кадре в начале окна или ещё
  был в конце.
- `coverage_ratio`, `processed_duration_s` — сколько видео реально декодировано.
- Ошибки: нет видео → `UNAVAILABLE` (`VIDEO_UNAVAILABLE`, `CAMERA_UNKNOWN`),
  истёк deadline → `TIMEOUT`, битое видео или сбой модели → `FAILED`
  (`DECODE_FAILED`, `MODEL_FAILED`, `GALLERY_UNAVAILABLE`). Пустой `DONE` —
  нормальный ответ «никого похожего нет».
- OPEN-проба (live): обрабатывает только интервал после durable checkpoint,
  люди в кадре в конце окна помечаются `open: true`; `cancel` закрывает поток
  (`stream_closed: true`).

Артефакты пишутся в `ArtifactStore` внутри кейса, их удаляет Retention:

```text
cases/{case_id}/perception/gallery/sources/0000.npz   векторы галереи
cases/{case_id}/perception/gallery/{gallery_ref}.npy  собранная галерея
cases/{case_id}/perception/embeddings/{tracklet}.npy  вектор трека
cases/{case_id}/perception/crops/{tracklet}.jpg       лучший кроп (миниатюра)
```

Галерея и векторы переживают перезапуск воркера. SQLite state дополнительно
хранит fingerprints/results заданий, gallery commands и OPEN checkpoints.

## Точность

Re-ID проверяется на открытом датасете **Market-1501** (1 501 человек,
6 камер). Обе модели обучены на другом датасете (MSMT17), то есть Market для них
«чужие камеры» — так же будет в реальном здании.

```bash
python -m javes_perception.eval_reid --data tmp/datasets/Market-1501-v15.09.15 \
  --model osnet_ain_x1_0 --weights models/osnet_ain_x1_0_msmt17.pt
```

- **Rank-1** — доля запросов, где первым в выдаче стоит тот же человек.
- **mAP** — насколько высоко в среднем стоят все правильные совпадения.
- «Трек» — запрос из среднего вектора нескольких кадров одного человека на одной
  камере, как в нашем конвейере.

| Вариант | Rank-1 (1 кадр) | mAP (1 кадр) | Rank-1 (трек) | mAP (трек) |
|---|---|---|---|---|
| OSNet x1.0, было | 57.2 % | 30.4 % | 66.5 % | 37.6 % |
| OSNet x1.0 + flip | 57.0 % | 30.5 % | 66.9 % | 37.7 % |
| OSNet-AIN x1.0 | 69.8 % | 43.3 % | 77.4 % | 50.9 % |
| **OSNet-AIN x1.0 + flip, сейчас** | **70.5 %** | **43.7 %** | **78.1 %** | **51.3 %** |

Главный прирост дала модель **OSNet-AIN**: она обучена так, чтобы меньше
зависеть от освещения и цветопередачи конкретной камеры. Усреднение по треку
добавляет ещё ~8 пунктов Rank-1, поэтому Perception всегда сравнивает вектор
трека, а не одного кадра. Зеркальный кроп даёт немного, но почти бесплатно.

Калибровка: на тех же данных логистическая регрессия по парам «тот же человек /
другой человек» дала `a = 26.0`, `b = -15.49`. Score 0.5 соответствует cosine
≈ 0.60; медиана cosine у одного человека 0.74, у разных 0.46 (99-й перцентиль
0.70). Порог `score_floor = 0.1` (cosine ≈ 0.51) отсекает большинство чужих.

Фильтр плохих кропов (обрезанные, перекрытые) на Market не измерить: там все
кропы уже чистые. Его эффект виден на видео, где в одну рамку часто попадают
двое.

## Проверка на складе NVIDIA (несколько камер)

Локальное demo-видео генерируется следующей командой и не хранится в Git.
Фото цели берётся с одной камеры, Perception находит этого человека на всех
четырёх (зелёная рамка).

```bash
python -m javes_perception.demo_video --query-camera Warehouse_Synthetic_Cam002 --query-time 20
```

Данные: синтетический склад из NVIDIA DeepStream MV3DT (Apache-2.0), 4 камеры
по 60 с и 12 камер по 20 с, синхронные и откалиброванные. Лежат в
`data/nvidia_mtmc/`. Market-1501 в репозиторий не входит (лицензия и 33 тыс.
файлов), его нужно скачать отдельно в `tmp/datasets/`.

Разметки людей в наборе нет, поэтому правда берётся из геометрии. Ноги
человека (низ рамки) через калибровку переводятся в точку пола склада. Если два
трека с разных камер в одни и те же моменты стоят в одной точке (медиана
расстояния < 1.5 единиц мира), это один человек. Сравниваются только треки,
которые пересекаются по времени: про остальных геометрия ничего не говорит.

```bash
python -m javes_perception.eval_mtmc --data data/nvidia_mtmc/mtmc_4cam --seconds 60
python -m javes_perception.eval_mtmc --data data/nvidia_mtmc/mtmc_12cam --seconds 20
```

«Фото → треки» — как в реальном поиске: лучший кроп человека с одной камеры
ищется среди треков других камер. Rank-1 — правильный человек оказался первым.

| Вариант | 4 камеры, фото → треки | 4 камеры, трек → треки | 12 камер, фото → треки | 12 камер, трек → треки |
|---|---|---|---|---|
| OSNet x1.0, без фильтра (было) | 88.6 % | 96.2 % | 92.7 % | 98.2 % |
| OSNet-AIN, без фильтра | 92.4 % | 100 % | 94.5 % | 94.5 % |
| **OSNet-AIN + фильтр кропов (сейчас)** | **97.4 %** | **100 %** | **100 %** | **98.0 %** |
| OSNet-AIN + фильтр + YOLO26s | 93.9 % | 98.5 % | 94.3 % | 96.2 % |

Выводы:

- Для сценария «фото → треки» фильтр плохих кропов даёт больше всего:
  +5 пунктов на 4 камерах и +5.5 на 12. Здесь его эффект наконец виден.
- Детектор побольше (YOLO26s) не помог: треков стало меньше, точность ниже.
  Остаёмся на `yolo26n`.
- **Калибровка не переносится между площадками.** У разных людей медиана
  cosine 0.44 на 4 камерах, но 0.64 на 12 камерах: там похожие синтетические
  модели людей. С калибровкой Market-1501 чужой человек на 12 камерах получает
  score около 0.7. Порядок кандидатов правильный, а абсолютный score нет.
  Калибровку нужно подбирать на камерах той площадки, где идёт поиск.
- Цифры оптимистичные: склад синтетический, освещение ровное, и на каждый
  запрос приходится лишь несколько кандидатов, которые были в кадре
  одновременно. На реальных камерах будет хуже.

## Запуск

```bash
python -m pip install -e '.[test,infra,perception]'
gdown "https://drive.google.com/uc?id=1SigwBE6mPdqiJMqhuIY4aqC7--5CsMal" -O models/osnet_ain_x1_0_msmt17.pt
javes-perception-probe --config perception.yaml --reference target.jpg \
  --camera cam_1 --from 2026-11-05T05:00:00Z --to 2026-11-05T05:00:50Z --out perception_out
```

`yolo26n.pt` Ultralytics скачивает сам. Устройство выбирается автоматически:
CUDA → Apple MPS → CPU. На Apple M5 50 секунд видео обрабатываются примерно за
6 секунд.

Подключение в систему: `javes-perception-worker --main-url ... --token ...
--worker-id ... --config perception.yaml --artifact-root ... --state-db ...`.

## Ограничения

- Калибровка подобрана на Market-1501, а не на наших камерах. На своих камерах
  её нужно перепроверить: та же команда `eval_reid` на размеченных кропах.
- `p_det` (как часто Perception пропускает человека) ещё не измерен.
- Видео читается из mp4-файлов; адаптер к настоящему архиву камер не написан.
- Worker публикует текущий JPEG/crop и bbox через LiveFeed endpoint; отдельный
  MJPEG/HLS encoder пока не реализован.
- Лицензия Ultralytics — AGPL-3.0 (для учебного проекта не мешает).
